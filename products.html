01 Consumer SaaS

Sundae Planner

An AI weekly-planning coach. You talk through the roles you play in life, it helps you plan actions for each one, puts the plan on your Google Calendar, and checks in every day.

Live in production
sundaeplanner.com Placeholder thumbnail · add img/sundae.jpg

PProblem

Weekly planning works when you do it, and almost nobody keeps doing it. Planner apps hold your list but never ask you about it, so the plan and the week drift apart by Tuesday.

DDecisions

  • Nothing touches your calendar until you approve it. The AI proposes; you confirm.
  • One function decides "done." Every screen shows the same score because only one piece of code computes it.
  • Channel-agnostic engines. Web, email, and text can all use the same conversation brain.

OShipped

  • A conversational weekly session that ends in confirmed calendar blocks.
  • A daily cron that follows up by email and reconciles goals against what happened.
  • Onboarding, trials, Stripe billing, analytics, and a custom domain. 114 commits in its first stretch, from Aug 4, 2026.

Grant & RFP agent team

A full-stack app for a grant-writing and government-contracting client. An orchestrator reads each request, sends it to the right specialist agent, and every agent shares one project memory.

PProblem

Grant and contracting work is mostly reading: eligibility rules, long RFPs, compliance checklists. Those are the parts a model can draft, but only if it keeps the client's context straight across many projects. [PLACEHOLDER: the client's before-state in one line]

DDecisions

  • Orchestrator plus specialists instead of one do-everything agent: grant specialist, contracting specialist, business assistant, personal agent.
  • One shared project memory so every agent works from the same facts.

OShipped

  • Knowledge base seeded with the client's own data, plus PDF upload.
  • Drive, Gmail, and Calendar connected through MCP. Built in daily sprints, each day's goal tracked in commits.

A personal operating system I own: a markdown library of everything I know, skills (written procedures an agent follows), scheduled jobs, and a team of agents that ships software.

PProblem

Every new chat starts from zero. I was re-explaining my classes, my clients, and my finances to a model that forgot them by the next session, and doing the same tasks by hand over and over.

DDecisions

  • Context lives on disk, in plain markdown I can read and edit, not inside one vendor's memory.
  • Do it once by hand, then make it a skill. Daily briefs, meeting prep, class notes, and inbox triage all started that way.
  • Models judge, code calculates. The household CFO agent never invents a number; scripts do the math.
  • People decide, agents do. Shipping code, writing to a calendar, or spending money waits for a human.

OShipped

  • Buzz software factory: Tyler scopes → Greg writes the PRD → Brad builds and runs types, lint, build → Quinton QAs against six repo rules → ship.
  • Household CFO agent: bank exports in, budget buckets, weekly check-ins, a monthly "money date."
  • Runs on Claude Code, Codex, or Hermes, with an always-on Mac Mini for long jobs.

04 MSB 341 product · BYU Marriott

My SI

A personal model benchmark built from your own work: it interviews you, turns your real tasks into tests, and tells you which AI model is actually best for you.

My SI prototype live
Try My SI

PProblem

Leaderboards test math olympiads, not the things people actually ask AI to do, so nobody knows which model is best for them.

DDecisions

  • Your work, not olympiad math. Test tasks come from an interview about what you actually do.
  • Blind ratings. You judge outputs without knowing which model wrote them.
  • Ship as an MCP connector. It runs inside the AI tools people already use.
  • Ties go to the cheaper, faster model. A rule that came straight from the first tester.

OShipped

  • My SI: an MCP connector that interviews you, builds test tasks from your real work, runs them on GPT, Gemini, and Claude, and has you rate them blind.
  • First outside tester: interview to ranking in about 15 minutes, for $0.07. Their three-way tie led to a rule: ties go to the cheaper, faster model.

05 Open-source SaaS

OpenCal

Free, open-source pickup booking: a TidyCal-style scheduler you host yourself. Clients open your link, tap a pickup time, leave their contact info, and it's booked — on your Google Calendar, never double-booked.

In progress
github.com/tyleramberry/opencal Placeholder thumbnail · add a booking-flow screenshot

PProblem

Small businesses pay monthly for a booking link that only does one thing. A bakery needed clients to book order pickups — one link, one 30-minute pickup type, a weekly handout schedule — without paying a subscription for it.

DDecisions

  • Study the incumbent, copy nothing. Built after studying TidyCal's public booking flow with a behavior-recording agent — behavior only, no copied code.
  • You host it. One shareable link per business (/<name>/pickup), self-hosted, MIT licensed.
  • Real calendar, race-safe. Google Calendar busy times block slots in real time; bookings serialize on a Postgres advisory lock so two people can't claim the last slot.
  • Phone required. Name, email, and phone on every booking, so the owner can call about an order.

OShipped

  • Month calendar with 30-minute slots, confirmation page with "Add to calendar" (.ics) and self-serve cancel links.
  • Optional confirmation and cancellation emails with the invite attached (Resend), plus the pickup address on every surface.
  • Admin at /admin: set hours and address, copy your link, see and cancel pickups.
  • Deploys to Cloudflare Workers with a hosted Postgres, or runs locally on embedded PGlite. [PLACEHOLDER: live demo link once deployed]

06 Open-source plugin · Nous Research hackathon

Hermes Multiplayer

Team chat inside Hermes: channels, DMs, and threads for you, up to four teammates, and everyone's Hermes agents — and the agents read and post in them right alongside you.

Listed in the plugin catalog
tyleramberry.github.io/hermes-multiplayer Placeholder thumbnail · add a chat screenshot

PProblem

Agents work alone. A team's Hermes agents couldn't see each other's work, and coordinating a shared build meant screenshots and copy-paste between people who each had a private agent.

DDecisions

  • Agents are first-class members. Your agent reads the channels, posts progress, and joins threads — the chat is a shared surface for humans and agents, not a human-only feed.
  • Your team owns the relay. Whoever runs a relay can read its messages, so there is no shared public relay: each team deploys its own on Cloudflare's free plan, in about ten minutes.
  • One-click install. Ships as a Hermes plugin with a hermes:// install deep link; setup is install → relay once per team → invite.

OShipped

  • Built for the Nous Research Hermes Agent Plugin Hackathon (Nov 2026) and listed in the Hermes plugin catalog.
  • Channels, direct messages, and threads, with invites by clipboard.
  • A Cloudflare Workers relay that holds messages while a laptop is closed, plus an install page and full non-technical setup docs.
